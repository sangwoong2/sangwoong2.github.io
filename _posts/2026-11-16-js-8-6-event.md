## 이벤트 핸들러

이벤트 핸들러는 이벤트가 일어났을 때 실행할 함수다. 태그의 `onClick`, `onChange` 같은 속성에 함수를 넘긴다.

```jsx
<button onClick={this.onClickSave}>저장</button>
```

### 넘기는 값

함수를 넘긴다. `( )` 를 붙이면 그릴 때 바로 호출되고 그 결과가 넘어간다.

```jsx
<button onClick={this.onClickSave}>저장</button>       // 클릭하면 호출된다
<button onClick={this.onClickSave()}>저장</button>     // render 할 때마다 호출된다
```

### 인자가 있을 때

화살표 함수로 감싸서 넘긴다.

```jsx
<button onClick={() => this.onClickStep('2')}>다음</button>
```

### this

메서드를 그대로 넘기면 핸들러 안의 `this` 가 `undefined` 다. 필드에 담은 화살표 함수는 `this` 가 유지된다.

```jsx
class Page extends React.Component {
    method() {
        console.log(this);      // undefined
    }

    field = () => {
        console.log(this);      // Page 인스턴스
    };

    render() {
        return (
            <>
                <button onClick={this.method}>메서드</button>
                <button onClick={this.field}>필드</button>
            </>
        );
    }
}
```

## 이벤트 객체

핸들러는 이벤트 객체를 인자로 받는다. React 가 넣어 주는 값이다.

| 속성 | 내용 |
| --- | --- |
| `e.target` | 이벤트가 일어난 요소 |
| `e.target.value` | 입력 요소의 현재 값 |
| `e.type` | 이벤트의 종류 (`'click'`, `'change'`) |
| `e.key` | 눌린 키 (`'Enter'`, `'a'`) |
| `e.preventDefault()` | 브라우저의 기본 동작을 막는다 |
| `e.stopPropagation()` | 부모 요소로 전달되는 것을 막는다 |

### 전파

자식 요소에서 일어난 이벤트는 부모 요소로 올라간다. 부모의 핸들러도 실행된다. `e.stopPropagation()` 을 호출하면 올라가지 않는다.

```jsx
<div onClick={() => console.log('div')}>
    <button onClick={() => console.log('button')}>클릭</button>
</div>
// 버튼을 누르면: 'button', 'div'
```

### 핸들러가 끝난 뒤

React 16 은 핸들러가 끝나면 이벤트 객체의 내용을 비운다. 나중에 실행되는 코드에서 읽으면 값이 없다.

```javascript
onChange = (e) => {
    setTimeout(() => {
        console.log(e.type);    // null
    }, 0);
};
```

나중에 쓸 값은 핸들러 안에서 먼저 변수에 꺼내 둔다.

```javascript
onChange = (e) => {
    const value = e.target.value;

    setTimeout(() => {
        console.log(value);     // 입력한 값
    }, 0);
};
```

`await` 뒤, `setState` 에 넘긴 함수 안에서 읽는 경우도 같다.

## 제어 입력

제어 입력은 입력 요소의 값을 state 로 정하는 방식이다. `value` 에 state 를 넘기고, `onChange` 에서 state 를 바꾼다.

```jsx
class Page extends React.Component {
    state = { name: '' };

    onChange = (e) => {
        this.setState({ name: e.target.value });
    };

    render() {
        return <input value={this.state.name} onChange={this.onChange} />;
    }
}
```

### 입력이 화면에 나오는 과정

1. 사용자가 글자를 입력한다.
2. `onChange` 가 호출되고 `e.target.value` 에 입력한 값이 들어 있다.
3. `setState` 로 state 를 바꾼다.
4. 다시 그려지면서 `value` 에 새 state 가 들어간다.

화면에 보이는 값은 항상 state 다.

### onChange 가 없을 때

`value` 만 넘기면 입력해도 값이 바뀌지 않는다. state 가 바뀌지 않으므로 다시 그릴 때 원래 값으로 돌아간다. 경고도 나온다.

```jsx
<input value={this.state.name} />
```


## 여러 입력을 한 핸들러로

입력 요소마다 구분할 값을 주고, 계산된 키로 해당 state 만 바꾼다.

```jsx
onChange = (e) => {
    const { id, value } = e.target;

    this.setState({ [id]: value });
};

render() {
    return (
        <>
            <input id="itemCd" value={this.state.itemCd} onChange={this.onChange} />
            <input id="itemNm" value={this.state.itemNm} onChange={this.onChange} />
        </>
    );
}
```

## 정리

- 이벤트 핸들러: 이벤트 속성에 함수를 넘긴다. `( )` 를 붙이면 그릴 때 호출된다.
- 메서드를 그대로 넘기면 `this` 가 `undefined` 다. 필드에 담은 화살표 함수를 넘긴다.
- 이벤트 객체는 React 가 인자로 넣어 준다. `e.target.value` 로 입력값을 읽는다.
- 이벤트는 부모 요소로 올라간다.
- React 16 에서는 핸들러가 끝나면 이벤트 객체가 비워진다. 나중에 쓸 값은 먼저 변수에 꺼낸다.
- 제어 입력: `value` 에 state 를 넘기고 `onChange` 에서 state 를 바꾼다.
