## 스코프 체인

스코프 체인은 안쪽 스코프에서 바깥 스코프로 이어지는 연결이다. 변수를 쓰면 이 연결을 따라 변수를 찾는다.

### 찾는 순서

지금 스코프에서 먼저 찾고, 없으면 바로 바깥 스코프, 거기도 없으면 그 바깥으로 올라간다. 끝까지 없으면 ReferenceError 다.

```javascript
const a = 1;

const outer = () => {
    const b = 2;

    const inner = () => {
        const c = 3;
        return a + b + c;   // c 는 여기서, b 는 outer 에서, a 는 맨 바깥에서 찾는다
    };

    return inner();
};

console.log(outer());   // 6
```

### 렉시컬 스코프

함수의 바깥 스코프는 함수를 **정의한 위치**로 정해진다. 어디서 호출했는지는 관계없다.

```javascript
const x = '바깥';

const show = () => x;

const run = () => {
    const x = '안쪽';
    return show();
};

console.log(run());     // '바깥'
```

`show` 는 `run` 안에서 호출됐지만 `run` 의 `x` 를 보지 않는다. `show` 가 정의된 곳의 바깥 스코프에 있는 `x` 를 본다.

### 바깥 변수의 재할당

안쪽에서 바깥 변수에 값을 넣으면 바깥 변수가 바뀐다.

```javascript
let count = 0;

const increase = () => {
    count = count + 1;
};

increase();
increase();

console.log(count);     // 2
```

### 매개변수

매개변수는 그 함수의 지역 변수다. 바깥 변수와 이름이 같아도 다른 변수이고, 매개변수에 값을 넣어도 바깥 변수는 바뀌지 않는다.

```javascript
let count = 0;

const set = (count) => {
    count = 5;
};

set(count);

console.log(count);     // 0
```

## 호이스팅

호이스팅은 선언이 스코프의 맨 위로 끌어올려진 것처럼 동작하는 것이다. 스코프가 시작될 때 그 안의 선언이 먼저 등록되기 때문에 생긴다.

### 선언별 차이

| 선언 | 선언 전에 쓰면 |
| --- | --- |
| `var` | `undefined` |
| `let`, `const` | ReferenceError |
| 함수 선언문 | 호출할 수 있다 |
| 변수에 담은 함수 | 그 변수의 규칙을 따른다 |
| `class` | ReferenceError |

### 함수 선언문

함수 전체가 등록된다. 선언한 줄보다 위에서 호출할 수 있다.

```javascript
console.log(hello());   // 'hi'

function hello() {
    return 'hi';
}
```

### 변수에 담은 함수

등록되는 것은 변수다. `const`, `let` 이면 선언 전에 쓸 수 없고, `var` 면 `undefined` 라서 호출할 수 없다.

```javascript
console.log(typeof hello);  // 'undefined'
hello();                    // TypeError: hello is not a function

var hello = function () {
    return 'hi';
};
```

## 정리

- 스코프 체인: 변수를 지금 스코프에서 찾고, 없으면 바깥 스코프로 올라가며 찾는다.
- 렉시컬 스코프: 함수의 바깥 스코프는 정의한 위치로 정해진다. 호출한 위치와 관계없다.
- 매개변수: 그 함수의 지역 변수다.
- 호이스팅: 선언이 스코프 맨 위로 끌어올려진 것처럼 동작하는 것.
- 함수 선언문은 선언 전에 호출할 수 있다. 변수에 담은 함수는 그 변수의 규칙을 따른다.
