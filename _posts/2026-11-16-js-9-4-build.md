## 빌드

빌드는 작성한 소스 코드를 브라우저가 실행할 수 있는 파일로 바꾸는 과정이다. 작성한 코드와 브라우저에서 실제로 실행되는 코드는 같지 않다.

### 빌드가 필요한 이유

| 작성한 코드 | 브라우저 |
| --- | --- |
| JSX | 이해하지 못한다 |
| 최신 문법 | 오래된 브라우저는 이해하지 못한다 |
| 수백 개의 파일과 `import` | 파일마다 따로 요청하면 느리다 |
| SCSS, 이미지 `import` | JS 문법이 아니다 |

### 빌드가 하는 일

| 단계 | 하는 일 | 도구 |
| --- | --- | --- |
| 변환 | JSX 와 최신 문법을 브라우저가 이해하는 문법으로 바꾼다 | Babel |
| 묶기 | `import` 로 연결된 파일들을 몇 개의 파일로 합친다 | webpack |
| 줄이기 | 공백을 없애고 이름을 짧게 바꿔 파일 크기를 줄인다 | Terser |

## 패키지

패키지는 다른 사람이 만들어 배포한 코드 묶음이다. npm 이라는 도구로 내려받아 쓴다.

### package.json

프로젝트의 정보와 필요한 패키지 목록을 적은 파일이다.

| 항목 | 내용 |
| --- | --- |
| `dependencies` | 실행에 필요한 패키지 |
| `devDependencies` | 개발과 빌드에만 필요한 패키지 |
| `scripts` | `npm run 이름` 으로 실행할 명령 |

```json
{
    "dependencies": {
        "react": "16.10.2",
        "moment": "^2.29.0"
    },
    "scripts": {
        "start": "webpack serve --mode development",
        "build": "webpack --mode production"
    }
}
```

### node_modules

내려받은 패키지가 들어 있는 폴더다. `import 'react'` 처럼 경로 없이 이름만 적으면 여기서 찾는다. `npm install` 로 다시 만들 수 있어서 저장소에는 올리지 않는다.

### 버전 표기

| 표기 | 설치되는 버전 |
| --- | --- |
| `16.10.2` | 정확히 그 버전 |
| `^2.29.0` | 2.29.0 이상, 3.0.0 미만 |
| `~2.29.0` | 2.29.0 이상, 2.30.0 미만 |
| `*` | 아무 버전 (가장 최신) |

범위로 적으면 설치하는 시점에 따라 다른 버전이 설치될 수 있다. 같은 소스인데 PC 마다 동작이 다른 원인이 된다.

### package-lock.json

실제로 설치된 버전을 정확히 기록한 파일이다. 이 파일이 있으면 다른 PC 에서도 같은 버전이 설치된다.

## Babel

Babel 은 코드를 다른 문법의 코드로 바꾸는 도구다.

### JSX

```jsx
const el = <div className="box">내용</div>;
```

```javascript
const el = React.createElement('div', { className: 'box' }, '내용');
```

### 최신 문법

```javascript
const name = user?.name ?? '없음';
```

```javascript
var _user$name;
var name = (_user$name = user === null || user === void 0 ? void 0 : user.name) !== null && _user$name !== void 0 ? _user$name : '없음';
```

문법은 바꿔 주지만, 브라우저에 없는 함수(`Array.prototype.flat` 등)를 만들어 주지는 않는다. 없는 함수를 채워 넣는 코드는 폴리필이라고 하고 따로 넣어야 한다.

## webpack

webpack 은 `import` 로 연결된 파일들을 따라가며 하나로 묶는 도구다.

### 시작 파일

시작 파일 하나에서 출발해서 그 파일이 `import` 하는 파일, 그 파일이 다시 `import` 하는 파일을 모두 찾아 묶는다. 어디서도 `import` 하지 않는 파일은 결과에 들어가지 않는다.

### 로더

JS 가 아닌 파일을 `import` 할 수 있게 바꿔 주는 장치다.

| `import` 하는 것 | 바뀌는 결과 |
| --- | --- |
| `.js` (JSX, 최신 문법) | 변환된 JS |
| `.scss`, `.css` | 화면에 적용되는 스타일 |
| `.png` 같은 이미지 | 그 파일의 주소 문자열 |

```javascript
import './Page.scss';              // 스타일이 화면에 적용된다
import icon from './icon.png';      // icon 은 이미지의 주소다
```

### 파일 나누기

`import()` 로 가져오는 파일은 별도의 파일로 나뉜다. 그 줄이 실행될 때 브라우저가 그 파일을 내려받는다. 화면을 열 때 그 화면의 코드를 받는 방식이 이것이다.

```javascript
const Page = React.lazy(() => import('./Page'));
```

## 개발 모드, 운영 모드

| | 개발 모드 | 운영 모드 |
| --- | --- | --- |
| 명령 | `npm start` | `npm run build` |
| 결과 | 메모리에 만들고 개발 서버가 제공한다 | 파일로 만들어진다 |
| 코드 | 읽을 수 있는 상태 | 줄여져 있다 |
| React 의 경고 | 콘솔에 나온다 | 나오지 않는다 |
| 소스를 고치면 | 자동으로 다시 빌드되고 화면에 반영된다 | 다시 빌드해야 한다 |

### 환경 변수

`process.env.이름` 은 빌드할 때 실제 값으로 바뀐다. 실행 중에 읽는 값이 아니라 빌드 결과에 문자열로 들어가 있는 값이다. 환경 변수를 바꾸면 다시 빌드해야 반영된다.

```javascript
if (process.env.NODE_ENV === 'development') {
    console.log('개발 모드에서만 실행된다');
}
```

## 소스맵

소스맵은 빌드된 코드의 위치와 원래 소스의 위치를 연결해 주는 파일이다. 소스맵이 있으면 개발자 도구에서 에러의 위치가 원래 파일의 줄 번호로 보이고, 원래 소스에 중단점을 걸 수 있다. 없으면 줄여진 코드의 위치로 보인다.

## 캐시

브라우저는 한 번 받은 파일을 저장해 두고 다시 쓴다. 새로 배포했는데 브라우저가 예전 파일을 쓰면 수정한 내용이 보이지 않는다. 빌드 결과의 파일 이름에 내용에 따라 달라지는 값을 붙여서, 내용이 바뀌면 다른 파일로 인식되게 한다.

```
main.3f2a91c.js
```

## 정리

- 빌드: 소스 코드를 브라우저가 실행할 수 있는 파일로 바꾸는 과정. 변환, 묶기, 줄이기를 한다.
- 패키지: 내려받아 쓰는 코드 묶음. `package.json` 에 목록이 있고 `node_modules` 에 설치된다.
- 버전을 범위로 적으면 설치 시점에 따라 다른 버전이 설치될 수 있다.
- Babel: JSX 와 최신 문법을 바꾼다. 없는 함수를 만들어 주지는 않는다.
- webpack: `import` 를 따라가며 파일을 묶는다. `import()` 로 가져오는 파일은 따로 나뉜다.
- 환경 변수: 빌드할 때 값으로 바뀐다.
- 소스맵: 빌드된 코드와 원래 소스의 위치를 연결한다.
