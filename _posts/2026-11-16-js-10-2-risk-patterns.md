## 증상에서 원인 찾기

증상을 보고 원인 후보를 좁히는 표다. 괄호 안은 그 내용을 다룬 글의 번호다.

### 화면이 바뀌지 않는다

| 원인 | 확인할 곳 |
| --- | --- |
| state 를 직접 수정했다 (8-2) | `this.state.값 = ...`, `this.state.배열.push(...)` |
| 같은 참조를 다시 넣었다 (8-7) | 배열이나 객체를 고친 뒤 그대로 `setState` |
| props 를 state 로 복사해 두었다 (8-3) | `state = { 값: this.props.값 }` |
| `setState` 가 호출되지 않았다 | 조건문, 조기 반환, 에러로 그 줄에 도달하지 못함 |

### 값이 이전 값이다

| 원인 | 확인할 곳 |
| --- | --- |
| `setState` 직후에 `this.state` 를 읽었다 (8-2) | `setState` 바로 다음 줄 |
| `await` 를 빼서 끝나기 전에 다음 줄이 실행됐다 (7-3) | 저장 뒤 조회 |
| 함수가 예전 변수를 붙잡고 있다 (4-3, 8-9) | 타이머, 구독, `useEffect` 안의 함수 |
| 필드에 복사해 둔 값을 읽는다 (5-2) | 필드 초기값에 `this.props` 의 값을 넣은 곳 |

### undefined 에서 속성을 읽었다는 에러

`Cannot read properties of undefined (reading 'x')` 는 `x` 앞의 값이 `undefined` 라는 뜻이다.

| 원인 | 확인할 곳 |
| --- | --- |
| 없는 속성, 범위 밖 인덱스 (3-1, 3-3) | `rows[0]` 인데 배열이 비어 있음 |
| `find` 가 찾지 못했다 (3-3) | `find(...)` 뒤에 바로 `.속성` |
| `await` 를 빼서 Promise 가 들어왔다 (7-3) | 서버 호출의 결과를 받는 줄 |
| `this` 를 잃었다 (4-4) | 메서드를 콜백으로 넘긴 곳 |
| ref 의 대상이 그려지지 않았다 (8-5) | `this.xxxRef.current.메서드()` |
| 조회가 끝나기 전에 그렸다 (8-4) | 초기 state 가 `null` 이거나 비어 있음 |

### NaN 이 나온다

| 원인 | 확인할 곳 |
| --- | --- |
| 숫자로 바꿀 수 없는 문자열 (2-2) | 쉼표가 든 금액, 단위가 붙은 값 |
| `undefined` 가 계산에 들어갔다 (1-2) | 없는 속성으로 계산 |
| 한 번 생긴 `NaN` 이 이어졌다 (2-2) | 처음 `NaN` 이 된 계산을 찾는다 |

### [object Object], [object Promise] 가 보인다

| 원인 | 확인할 곳 |
| --- | --- |
| 객체를 문자열에 이어 붙였다 (1-2) | `'...' + 객체`, 템플릿 문자열 안의 객체 |
| `await` 를 뺀 Promise 를 이어 붙였다 (7-2) | 서버 호출 결과를 바로 문자열에 넣음 |
| 저장소에 객체를 그대로 넣었다 (9-1) | `setItem(키, 객체)` |

### 화면에 0 이 나온다

| 원인 | 확인할 곳 |
| --- | --- |
| `&&` 의 왼쪽이 숫자다 (8-1) | `{rows.length && <Grid />}` |

### 가끔만 틀린다

| 원인 | 확인할 곳 |
| --- | --- |
| 응답이 요청한 순서대로 오지 않았다 (7-5) | 조건을 빠르게 바꿔 연속 조회 |
| `await` 사이에 값이 바뀌었다 (7-5) | `await` 전에 읽은 값을 `await` 뒤에 사용 |
| `forEach` 안의 `async` 를 기다리지 않았다 (7-5) | `forEach(async ...)` 다음 줄 |
| 컴포넌트가 사라진 뒤 응답이 왔다 (8-4) | 화면을 닫은 직후의 경고 |

### 금액이 1 차이 난다

| 원인 | 확인할 곳 |
| --- | --- |
| 소수점 오차 뒤에 반올림했다 (2-2) | `Math.round(값 * 100) / 100`, `toFixed` |
| `toFixed` 의 결과(문자열)로 계산했다 (2-2) | `toFixed(...)` 뒤의 `+` |
| 행마다 반올림한 합과 합계를 반올림한 값이 다르다 | 반올림하는 위치 |

### 날짜가 하루 다르다

| 원인 | 확인할 곳 |
| --- | --- |
| `'YYYY-MM-DD'` 문자열을 Date 로 만들었다 (2-3) | `new Date('2026-11-16')` |
| `toISOString` 으로 날짜를 만들었다 (2-3) | `toISOString().slice(0, 10)` |
| 월을 1 부터 센 숫자로 넣었다 (2-3) | `new Date(연, 월, 일)`, `getMonth()` |

### 정렬이 이상하다

| 원인 | 확인할 곳 |
| --- | --- |
| 비교 함수 없이 숫자를 정렬했다 (3-3) | `.sort()` |
| 비교 함수가 불리언을 돌려준다 (3-3) | `sort((a, b) => a > b)` |
| 숫자가 문자열로 들어 있다 (2-1) | `'10' < '9'` |

### 다른 데이터가 같이 바뀐다

| 원인 | 확인할 곳 |
| --- | --- |
| 같은 객체를 두 곳에서 가리킨다 (1-4) | 할당만 하고 복사하지 않음 |
| 얕은 복사라 안쪽 객체를 함께 쓴다 (1-4) | `{ ...객체 }` 뒤에 안쪽 속성 수정 |
| 원본을 바꾸는 메서드를 썼다 (3-3) | `sort`, `splice`, `push`, `reverse` |
| `moment` 의 `add`, `subtract` (2-3) | `clone()` 없이 계산 |
| `find` 가 돌려준 객체를 고쳤다 (3-3) | `find(...)` 결과의 속성에 할당 |

### 로딩이 끝나지 않는다

| 원인 | 확인할 곳 |
| --- | --- |
| 실패했을 때 해제하는 코드가 없다 (7-5) | `finally` 가 없는 `try/catch` |
| Promise 가 끝나지 않는다 (7-2, 7-5) | `resolve` 를 호출하지 않는 `new Promise` |

### 실패했는데 아무 표시가 없다

| 원인 | 확인할 곳 |
| --- | --- |
| `catch` 가 비어 있다 (6-2) | `catch (e) { }` |
| `await` 하지 않아 `try` 가 잡지 못했다 (7-3) | `try` 안의 `await` 없는 호출 |
| `finally` 에서 `return` 했다 (6-2) | `finally { return ... }` |
| 서버가 실패로 응답했는데 확인하지 않았다 (9-2) | 응답의 성공 여부를 보지 않음 |

### 화면이 느리거나 멈춘다

| 원인 | 확인할 곳 |
| --- | --- |
| 오래 걸리는 계산이 스레드를 붙잡는다 (7-1) | 큰 배열의 반복, 중첩된 반복 |
| 필요 없이 다시 그린다 (8-7) | `render` 안에서 만든 함수와 객체를 props 로 넘김 |
| `setState` 가 여러 번 호출된다 (8-2) | `await` 뒤의 연속된 `setState` |
| 조회를 순서대로 기다린다 (7-4) | 관계없는 조회를 한 줄씩 `await` |
| `componentDidUpdate` 가 반복된다 (8-4) | 조건 없는 `setState` |

### 닫은 화면에서 경고가 나온다

| 원인 | 확인할 곳 |
| --- | --- |
| 타이머, 이벤트, 구독을 해제하지 않았다 (8-4) | `componentWillUnmount` |

## 코드 모양에서 위험 찾기

코드를 읽을 때 아래 모양이 보이면 옆의 내용을 확인한다.

### 값과 타입

| 코드 모양 | 확인할 것 |
| --- | --- |
| `==`, `!=` | 형변환을 의도한 것인가 (1-2) |
| `값 || 기본값` | `0` 과 빈 문자열이 유효한 값인가. 그렇다면 `??` (1-3) |
| `if (배열)`, `if (객체)` | 빈 배열과 빈 객체도 참이다 (1-3) |
| `a.b.c.d` | 중간 값이 없을 수 있는가 (1-3) |
| `const b = a` 뒤에 `b` 수정 | `a` 도 바뀐다 (1-4) |

### 문자열·숫자·날짜

| 코드 모양 | 확인할 것 |
| --- | --- |
| `Number(입력값)`, `parseInt(입력값)` | 빈 값, 쉼표, 소수가 들어올 때의 결과 (2-2) |
| `toFixed(n)` 뒤의 계산 | 문자열이다 (2-2) |
| 소수의 곱셈 뒤 `Math.round` | 소수점 오차 (2-2) |
| `.replace('문자열', ...)` | 처음 하나만 바뀐다 (2-1) |
| `new Date('YYYY-MM-DD')` | UTC 0시로 해석된다 (2-3) |
| `moment(a).add(...)` 를 변수에 다시 사용 | 원본이 바뀐다 (2-3) |

### 배열과 객체

| 코드 모양 | 확인할 것 |
| --- | --- |
| `.sort(` | 원본이 바뀐다. 숫자면 비교 함수가 있는가 (3-3) |
| `.find(...)` 뒤의 `.속성` | 못 찾으면 `undefined` 다 (3-3) |
| `.map(...)` 의 콜백에 `{ }` | `return` 이 있는가 (3-3) |
| `.reduce(...)` | 초기값이 있는가 (3-3) |
| `for (const i in 배열)` | 인덱스가 문자열이다 (3-3) |
| `JSON.parse(...)` | 형식이 틀리면 에러가 난다. `try` 안에 있는가 (3-4) |
| `JSON.parse(JSON.stringify(...))` | `undefined`, 함수, Date 가 사라지거나 바뀐다 (1-4) |

### 함수와 클래스

| 코드 모양 | 확인할 것 |
| --- | --- |
| `onClick={this.메서드}` | 메서드가 아니라 필드에 담은 화살표 함수인가 (4-4) |
| `onClick={this.함수()}` | 그릴 때 호출된다 (8-6) |
| 필드 초기값의 `this.다른필드` | 그 필드가 위에 선언되어 있는가 (5-1) |
| `return` 다음 줄에 값 | `undefined` 를 돌려준다 (4-1) |
| `forEach` 콜백 안의 `return` | 그 콜백만 끝난다 (4-5) |

### 에러 처리와 비동기

| 코드 모양 | 확인할 것 |
| --- | --- |
| `catch (e) { }` | 실패가 남지 않는다 (6-2) |
| `try` 안의 `await` 없는 호출 | 실패를 잡지 못한다 (7-3) |
| Promise 를 돌려주는 함수를 `await` 없이 호출 | 의도한 것인가 (7-3) |
| `forEach(async ...)` | 기다리지 않는다 (7-5) |
| `new Promise(...)` 안에서 다른 Promise 사용 | `reject` 가 연결되어 있는가 (7-5) |
| 로딩을 `try` 안에서 해제 | 실패하면 해제되지 않는다 (7-5) |
| 연속된 `await` | 서로 관계없는 호출이면 병렬로 (7-4) |

### React

| 코드 모양 | 확인할 것 |
| --- | --- |
| `this.state.값 = ...`, `this.state.배열.push` | 다시 그려지지 않는다 (8-2) |
| `setState` 다음 줄의 `this.state` | 이전 값이다 (8-2) |
| `setState({ 키: this.state.키 + 1 })` 가 연속 | 함수형으로 (8-2) |
| `key={index}` | 순서가 바뀌거나 삭제되는 목록인가 (8-1) |
| `{숫자 && <태그 />}` | `0` 이 화면에 나온다 (8-1) |
| `state = { 값: this.props.값 }` | props 가 바뀌어도 따라가지 않는다 (8-3) |
| `setInterval`, `addEventListener` | 해제하는 코드가 있는가 (8-4) |
| `componentDidUpdate` 안의 `setState` | 조건이 있는가 (8-4) |
| `this.xxxRef.current.` | 대상이 그려지지 않았을 수 있는가 (8-5) |
| 핸들러의 `await` 뒤에서 `e.` 사용 | 이벤트 객체가 비워져 있다 (8-6) |

## 정리

- 증상에서 시작할 때: 증상에 해당하는 표에서 원인 후보를 고르고, "확인할 곳"의 코드를 찾는다.
- 코드에서 시작할 때: 표의 모양이 보이면 옆의 내용을 확인한다.
- 에러 없이 틀린 값이 나오는 경우가 가장 찾기 어렵다. 타입 변환, 못 찾았을 때의 값, 빠진 `await`, 원본 변경이 여기에 해당한다.
