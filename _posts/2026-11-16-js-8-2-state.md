## state

state 는 컴포넌트가 갖고 있는 데이터다. state 가 바뀌면 React 가 `render` 를 다시 호출해서 화면을 다시 그린다.

```jsx
class Page extends React.Component {
    state = { count: 0, name: '화면' };

    render() {
        return <div>{this.state.count}</div>;
    }
}
```

---

## setState

`this.setState(값)` 은 state 를 바꾸고 다시 그리도록 React 에 요청한다.

### 병합

넘긴 객체의 키만 바뀌고 나머지 키는 그대로 남는다.

```javascript
// state: { count: 0, name: '화면' }
this.setState({ count: 1 });
// state: { count: 1, name: '화면' }
```

병합은 한 단계만 한다. 값이 객체인 키는 통째로 바뀐다.

```javascript
// state: { sub: { x: 1, y: 1 } }
this.setState({ sub: { x: 9 } });
// state: { sub: { x: 9 } }     (y 가 사라진다)
```

안쪽 키 하나만 바꾸려면 기존 내용을 펼쳐서 새 객체를 만든다.

```javascript
this.setState({ sub: { ...this.state.sub, x: 9 } });
```

### 직접 수정

`this.state` 에 직접 값을 넣으면 값은 바뀌지만 다시 그려지지 않는다. React 는 `setState` 가 호출되어야 바뀐 것을 안다.

```javascript
this.state.count = 5;       // 화면이 바뀌지 않는다
```

## 반영 시점

### 이벤트 핸들러 안

`setState` 를 호출해도 `this.state` 는 바로 바뀌지 않는다. React 가 핸들러 안의 `setState` 를 모아 두었다가 핸들러가 끝난 뒤에 한 번에 반영하고 한 번만 다시 그린다.

```javascript
onClick = () => {
    // this.state.count 는 0
    this.setState({ count: this.state.count + 1 });

    console.log(this.state.count);  // 0  (아직 바뀌지 않았다)
};
```

### 여러 번 호출

같은 핸들러 안에서 `this.state` 를 읽어 여러 번 호출하면, 매번 바뀌기 전의 값을 읽는다.

```javascript
onClick = () => {
    // this.state.count 는 0
    this.setState({ count: this.state.count + 1 });     // { count: 1 }
    this.setState({ count: this.state.count + 1 });     // { count: 1 }
    this.setState({ count: this.state.count + 1 });     // { count: 1 }
};
// 결과: count 는 1, render 는 한 번
```

### 핸들러 밖

`setTimeout` 의 콜백이나 `await` 뒤처럼 React 의 이벤트 핸들러가 끝난 뒤에 실행되는 코드에서는, React 16 은 `setState` 를 모으지 않는다. 호출하는 즉시 반영하고, 호출할 때마다 다시 그린다.

```javascript
onClick = async () => {
    await save();

    this.setState({ count: 1 });
    console.log(this.state.count);  // 1  (바로 바뀌어 있다)

    this.setState({ count: 2 });    // render 가 한 번 더 호출된다
};
```

| `setState` 를 호출한 곳 | `this.state` 반영 | 다시 그리는 횟수 |
| --- | --- | --- |
| 이벤트 핸들러 안 | 핸들러가 끝난 뒤 | 모아서 한 번 |
| `setTimeout`, `await` 뒤 (React 16) | 호출 즉시 | 호출할 때마다 |

## 함수를 넘기는 setState

`this.setState((이전 state) => 바꿀 값)` 형태다. React 가 함수를 호출하면서 그 시점의 최신 state 를 넣어 준다.

```javascript
onClick = () => {
    // this.state.count 는 0
    this.setState((prev) => ({ count: prev.count + 1 }));   // 0 → 1
    this.setState((prev) => ({ count: prev.count + 1 }));   // 1 → 2
    this.setState((prev) => ({ count: prev.count + 1 }));   // 2 → 3
};
// 결과: count 는 3
```

---

## setState 의 콜백

`this.setState(값, 함수)` 의 두 번째 인자는 state 가 반영되고 다시 그려진 뒤에 호출된다. 그 안에서 읽는 `this.state` 는 바뀐 값이다.

```javascript
onClick = () => {
    this.setState({ count: 100 }, () => {
        console.log(this.state.count);  // 100
    });

    console.log(this.state.count);      // 0
};
```

바뀐 state 로 이어서 할 일(조회 등)을 이 콜백에 넣는다.

---

## 객체, 함수, 콜백 비교

| 형태 | 쓰는 경우 |
| --- | --- |
| `setState({ a: 1 })` | 넣을 값이 정해져 있을 때 |
| `setState((prev) => ({ a: prev.a + 1 }))` | 이전 state 로 새 값을 계산할 때 |
| `setState({ a: 1 }, () => { })` | 반영된 뒤에 이어서 할 일이 있을 때 |

---

## 다시 그리는 조건

| 호출 | `React.Component` 에서 다시 그리는가 |
| --- | --- |
| `setState({ count: 같은 값 })` | 그린다 |
| `setState(null)` | 그리지 않는다 |
| `this.state.count = 값` | 그리지 않는다 |
| `forceUpdate()` | 그린다 |

`setState` 를 호출하면 값이 같아도 `render` 가 다시 호출된다. 값을 비교해서 건너뛰는 것은 8-7 "PureComponent와 다시 그리기"에서 다룬다.

## 정리

- state: 컴포넌트가 갖는 데이터. 바뀌면 `render` 가 다시 호출된다.
- `setState`: 넘긴 키만 바꾼다. 병합은 한 단계만 한다.
- `this.state` 를 직접 수정하면 다시 그려지지 않는다.
- 이벤트 핸들러 안에서는 `setState` 직후에 `this.state` 를 읽어도 이전 값이다.
- 이전 state 로 계산할 때는 함수를 넘긴다.
- 반영된 뒤에 할 일은 `setState` 의 두 번째 인자로 넘긴다.
- React 16 에서 `setTimeout`, `await` 뒤의 `setState` 는 호출 즉시 반영되고 호출할 때마다 다시 그린다.
