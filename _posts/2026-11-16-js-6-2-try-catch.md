## 에러

에러는 실행을 계속할 수 없는 상황을 나타내는 객체다. 에러가 던져지면 그 자리에서 실행이 멈추고, 잡는 곳을 찾을 때까지 호출한 쪽으로 거슬러 올라간다.

### Error 객체

| 속성 | 내용 |
| --- | --- |
| `name` | 에러의 종류 |
| `message` | 에러의 설명 |
| `stack` | 에러가 난 위치와 호출 경로 |

```javascript
const e = new Error('조회 실패');

console.log(e.name);        // 'Error'
console.log(e.message);     // '조회 실패'
console.log(String(e));     // 'Error: 조회 실패'
```

### JSON 변환

`JSON.stringify` 에 Error 객체를 넘기면 내용이 나오지 않는다. `message` 를 직접 꺼내야 한다.

```javascript
console.log(JSON.stringify(new Error('조회 실패')));    // '{}'
```

### 에러의 종류

| 종류 | 나는 경우 | 예 |
| --- | --- | --- |
| TypeError | 값의 타입이 맞지 않는 동작 | `null.a`, `undefined()` |
| ReferenceError | 없는 변수를 썼을 때 | 선언하지 않은 변수 |
| SyntaxError | 문법이 틀렸을 때 | `JSON.parse('{')` |
| RangeError | 값이 허용 범위를 벗어났을 때 | `new Array(-1)` |

## throw

`throw 값` 은 에러를 던지는 문장이다. 그 줄에서 실행이 멈춘다.

```javascript
const check = (qty) => {
    if (qty < 0) {
        throw new Error('수량은 0 이상이어야 합니다.');
    }
    return qty;
};
```

### 던질 수 있는 값

아무 값이나 던질 수 있다. Error 객체가 아닌 값을 던지면 `stack` 이 없어서 어디서 났는지 알 수 없다.

```javascript
try {
    throw { code: 'E01', message: '실패' };
} catch (e) {
    console.log(e.message);             // '실패'
    console.log(e instanceof Error);    // false
    console.log(e.stack);               // undefined
}
```

## try/catch/finally

| 블록 | 실행되는 때 |
| --- | --- |
| `try` | 항상 |
| `catch` | `try` 안에서 에러가 던져졌을 때 |
| `finally` | 항상. 에러가 났든 안 났든 마지막에 |

### 실행 순서

에러가 난 줄에서 `try` 의 나머지를 건너뛰고 `catch` 로 간다.

```javascript
const order = [];

try {
    order.push('try');
    throw new Error('실패');
    order.push('실행되지 않는다');
} catch (e) {
    order.push('catch');
} finally {
    order.push('finally');
}
order.push('다음 줄');

console.log(order);     // ['try', 'catch', 'finally', '다음 줄']
```

### 에러 전에 실행된 것

되돌려지지 않는다. 에러가 나기 전에 바꾼 값은 바뀐 채로 남는다.

```javascript
const rows = [];

try {
    rows.push(1);
    null.a;         // 에러
    rows.push(2);
} catch (e) { }

console.log(rows);  // [1]
```

### finally 와 return

`try` 에서 `return` 해도 `finally` 는 실행된다.

```javascript
const order = [];

const run = () => {
    try {
        return 'try';
    } finally {
        order.push('finally');
    }
};

console.log(run());     // 'try'
console.log(order);     // ['finally']
```

`finally` 안에서 `return` 하면 그 값이 결과가 된다. 던져진 에러도 사라진다.

```javascript
const run = () => {
    try {
        throw new Error('실패');
    } finally {
        return 'finally';
    }
};

console.log(run());     // 'finally'  (에러가 밖으로 나가지 않는다)
```

### try 블록의 변수

`try` 안에서 선언한 변수는 `try` 블록 안에서만 쓸 수 있다. `catch` 나 그 뒤에서 쓰려면 `try` 밖에서 선언한다.

```javascript
let rows = [];

try {
    rows = JSON.parse(text);
} catch (e) {
    rows = [];
}
```

## 에러의 전달

에러를 잡지 않으면 그 함수를 호출한 쪽으로 올라간다. 올라가는 도중의 함수들은 에러가 난 자리에서 실행이 끝난다.

```javascript
const c = () => { throw new Error('깊은 곳'); };
const b = () => c();
const a = () => {
    try {
        b();
    } catch (e) {
        return 'a 에서 잡음: ' + e.message;
    }
};

console.log(a());   // 'a 에서 잡음: 깊은 곳'
```

끝까지 아무도 잡지 않으면 실행 중이던 작업이 거기서 끝나고 콘솔에 에러가 출력된다.

## catch 에서 하는 일

### 비워 두기

에러를 잡고 아무것도 하지 않으면 에러가 없었던 것처럼 다음 줄로 넘어간다. 실패한 사실과 원인이 어디에도 남지 않는다.

```javascript
let rows = ['이전 데이터'];

try {
    rows = JSON.parse('잘못된 문자열');
} catch (e) { }

console.log(rows);  // ['이전 데이터']  (실패했는데 이전 값으로 계속 진행된다)
```

### 다시 던지기

잡은 에러를 `throw e` 로 다시 던지면 바깥으로 계속 올라간다. 정리 작업만 하고 처리는 바깥에 맡길 때 쓴다.

```javascript
try {
    try {
        throw new Error('실패');
    } catch (e) {
        // 정리 작업
        throw e;
    }
} catch (e) {
    console.log('바깥에서 잡음: ' + e.message);     // '바깥에서 잡음: 실패'
}
```

### 감싸서 던지기

원래 에러의 내용을 담은 새 에러를 던진다.

```javascript
try {
    try {
        null.a;
    } catch (e) {
        throw new Error('조회 실패: ' + e.message);
    }
} catch (e) {
    console.log(e.message);     // "조회 실패: Cannot read properties of null (reading 'a')"
}
```

## try 로 잡을 수 없는 에러

`try` 는 블록 안의 코드가 실행되는 동안 던져진 에러만 잡는다. 나중에 실행되는 콜백에서 난 에러는 잡지 못한다. 콜백이 실행될 때는 `try` 블록이 이미 끝나 있기 때문이다.

```javascript
try {
    setTimeout(() => {
        throw new Error('나중에 난 에러');  // 바깥의 catch 로 가지 않는다
    }, 0);
} catch (e) {
    console.log('잡히지 않는다');
}
```

콜백 안에서 직접 잡아야 한다. `await` 를 쓰는 비동기 함수의 에러는 7-3 "async/await"에서 다룬다.

## 직접 만든 에러

`Error` 를 상속해서 만든다. 종류를 구분하거나 추가 정보를 담을 때 쓴다.

```javascript
class ValidationError extends Error {
    constructor(message, field) {
        super(message);
        this.name = 'ValidationError';
        this.field = field;
    }
}

try {
    throw new ValidationError('필수 항목입니다.', 'qty');
} catch (e) {
    console.log(e instanceof ValidationError);  // true
    console.log(e.field);                       // 'qty'
}
```

## 정리

- 에러: 실행을 계속할 수 없는 상황을 나타내는 객체. `name`, `message`, `stack` 을 갖는다.
- `throw`: 에러를 던진다. 그 줄에서 실행이 멈춘다.
- `try` 안에서 에러가 나면 나머지를 건너뛰고 `catch` 로 간다. 그 전에 바꾼 값은 되돌려지지 않는다.
- `finally`: 항상 실행된다. 안에서 `return` 하면 에러가 사라진다.
- 잡지 않은 에러는 호출한 쪽으로 올라간다.
- `catch` 를 비워 두면 실패한 사실이 남지 않는다.
- 나중에 실행되는 콜백의 에러는 바깥의 `try` 로 잡을 수 없다.
